# AIT-ADS saved-score evaluation subset

This bundle recomputes selected AIT-ADS manuscript results from sealed prediction scores, validation thresholds, session labels and session record counts. It contains 80 fold/seed cells for 6/1/1 and 4/2/2, with validation and test predictions for three configurations: `111` (full AUGUR), `011` (no state, edits and local scoring), and `current_only` (current-session baseline). It is a post-training evaluation artifact; it does **not** provide raw data, preprocessing, models, training, complete baselines or independently verified ground truth.

For each cell the archive contains arrays limited to generated scene/session IDs, policy-derived binary labels and the three corresponding scores. The session-cost file contains only the same derived IDs, labels, and per-session alert counts. It contains no alert message or raw event text. Identifiers are pseudonymous derived dataset references, not a guarantee of comprehensive anonymity or re-identification resistance.

Data attribution: Max Landauer, Florian Skopik, Markus Wurzenberger, *AIT Alert Data Set*, Zenodo (2023), DOI https://doi.org/10.5281/zenodo.8263181, Creative Commons Attribution 4.0 International, https://creativecommons.org/licenses/by/4.0/. The original data were grouped into sessions, assigned study-specific policy labels, and used to produce model scores and derived record counts. This is not the original dataset. Attribution from the prior published score archive is included inside the ZIP.

## Verify

Install the versions in `requirements.txt`; run `python verify_minimal_ait_repro.py`. The verifier reads the ZIP without extracting files, recomputes 240 validation-set cutoffs across 80 cells, AP, Recall@1% FPR and frozen-threshold outcomes per scene, and the equal-record-budget results. It compares them with the included reference metrics and writes `verification_result.json`. In the 4/2/2 protocol, scenes repeat across folds and fixed-budget counts are not unique sessions. Training scenes informed earlier research. All results are derived from saved scores and labels, not an independent retraining or deployment check.

`input_hashes.json` records input archive and output hashes for lineage. Source archives are not included and their availability is not implied. The archive contains only derived pseudonymous session identifiers, labels, scores, and record counts. These identifiers are linkable within the dataset, so this release does not guarantee comprehensive anonymization or re-identification resistance. The source dataset attribution and license are included. The separately authored verification script uses NumPy; see their respective licenses.
